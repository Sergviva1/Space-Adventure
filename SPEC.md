# План подготовки игры к портфолио

## Текущее состояние

Это небольшая 2D-игра на C++17 и SFML 3: игрок управляет кораблём, уклоняется от метеорита, собирает монеты и подбирает лечение. В проекте уже есть главное меню, анимация игрока, здоровье, очки, музыка и звуковые эффекты. Это хорошая основа для законченного учебного проекта.

Пока репозиторию не хватает нескольких вещей, которые помогают незнакомому человеку быстро понять, запустить и оценить игру: подробной страницы проекта, предсказуемой сборки и запуска, устойчивой логики игровых состояний и наглядной демонстрации. Ниже — план по приоритетам. Он описывает целевое состояние, а не означает, что все пункты уже реализованы.

## Журнал работы

### Выполнено (шаг P0-2: запуск и ресурсы)

- Ресурсы перенесены из `coding/assets/` в `assets/` рядом с исполняемым файлом. Добавлен шрифт `assets/PT_Sans-Regular.ttf` (SIL OFL) и `assets/PT_Sans-LICENSE.txt`.
- В `coding/main.cpp` добавлены `#include <filesystem>`, `<iostream>`, `<stdexcept>`, `<string>`.
- Добавлены хелперы: `executable_dir()` (каталог `main.exe` через Windows API), `asset_path(name)` (полный путь к `assets/...`), `require_loaded(ok, path)` (понятная ошибка загрузки).
- Все пути к игровым ресурсам заменены на `asset_path(...)`; файлы находятся в корневом `assets/`.
- Системный `C:/Windows/Fonts/Arial.ttf` заменён на `assets/PT_Sans-Regular.ttf`.
- Каталог исполняемого файла определяется через Windows API `GetModuleFileNameW`; сообщения об ошибках загрузки включают путь к ресурсу.
- `mingw32-make clean` и `mingw32-make` прошли успешно.
- Собранный `main.exe` запускался из другой рабочей папки и оставался открытым; это подтвердило загрузку ресурсов и runtime-DLL. Полное прохождение игры вручную не проверялось.
- Запуск тестовой копии без `assets/spritelist.png` завершился ожидаемой ошибкой с путём к отсутствующему файлу.
- Проверка DLL через `objdump` подтвердила нужные runtime-файлы; список добавлен в README.
- Установлено, что DLL MinGW из корня проекта конфликтуют с DLL компилятора при сборке из этой папки. Makefile теперь задаёт пользовательскую временную папку `%LOCALAPPDATA%\Temp` и запускает компилятор там с абсолютными путями; это устранило сбой.

- В окружении агента команда `make` отсутствует; `mingw32-make clean` и `mingw32-make` проверены из Windows shell и MSYS2 UCRT64.
