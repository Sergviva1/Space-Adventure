# Аудит старых ресурсов в истории Git

## Область проверки

Проверен локальный репозиторий на коммите `deb9e43110e46c26338f5b3536d7eb82470b9409`: 49 коммитов, достижимых через `git rev-list --all`. Проверены деревья всех этих коммитов, а не только список удалённых файлов. История, ветки и рабочие игровые ресурсы не изменялись; сетевой fetch не выполнялся.

Локальные ссылки: `main`, `origin/main`, `origin/HEAD`, `origin/bugfix/issues`. Локальных тегов нет. `git ls-remote --heads --tags origin` показал только удалённую ветку `main` на том же коммите. Следовательно, `origin/bugfix/issues` — оставшаяся локальная remote-tracking ссылка, а не подтверждение существования этой ветки на сервере.

Не проверены скрытые ссылки GitHub (включая pull request), форки, чужие клоны, reflog и недостижимые объекты. Переписывание ветки само по себе не гарантирует удаления таких копий.

## Результат

Найдены **18 уникальных старых медиаобъектов Git**, отсутствующих среди текущих ресурсов `HEAD:assets/`, общим размером **9 619 864 байта** (около 9,17 МиБ без сжатия). Это кандидаты на очистку согласно отсутствию подтверждённых прав в `CREDITS.md`, а не автоматическое юридическое заключение по содержимому файлов.

Всего 17 имён файлов, 18 уникальных объектов содержимого. Имена вида `*1.png` и `space1.jpg`, упоминавшиеся в прежней документации, в проверенной достижимой истории не найдены. Реальное старое имя фона — `space.jpg`.

Старые ресурсы перемещены из `coding/assets/` в `assets/` коммитом `22fc318`; в `cf93f5c` они удалены или заменены. Поэтому удаление только исторического каталога `coding/assets/` оставит старые копии в `assets/`.

**Не следует удалять все версии по совпадающим путям:** актуальные текстуры используют те же имена. У 17 нынешних медиафайлов `assets/` содержимое отличается от всех 18 кандидатов. Актуальные ресурсы должны быть сохранены.

Полные object ID, размеры, все найденные пути каждого объекта и первый просмотренный коммит сохранены в [asset-history-audit.json](asset-history-audit.json). Поле `first_seen_commit` означает первый коммит при обратном топологическом обходе, а не гарантированную единственную точку появления в разветвлённой истории.

## Повторение аудита

Из корня репозитория с Python 3 и Git в PATH:

```text
python scripts/audit-asset-history.py
```

Скрипт только читает Git и перезаписывает JSON-отчёт. Он выделяет медиаобъекты из двух каталогов ресурсов, отсутствующие среди текущих `HEAD:assets/`, и ищет другие пути тех же объектов во всех просмотренных деревьях. После добавления новых версий ресурсов список кандидатов требует повторного ручного рассмотрения.

## Предлагаемая очистка публичной истории

Предпочтительный вариант для сохранения истории разработки: в отдельном зеркальном клоне удалить **18 конкретных blob ID** из отчёта через `git filter-repo --strip-blobs-with-ids`, а не удалять все версии совпадающих путей.

До выполнения требуется:

1. Согласовать переписывание истории и последующий force-push. Не выполнять в текущей рабочей копии с незакоммиченными изменениями документации и скриптов.
2. Создать приватную резервную копию репозитория вне публичной раздачи и отдельно сохранить незакоммиченные изменения: Git bundle их не содержит.
3. В отдельном клоне проверить, что все 18 объектов перестали быть достижимыми через публикуемые ссылки, а дерево актуального коммита до и после очистки совпадает.
4. Выполнить сборку и smoke-проверку очищенного проекта, затем обновить согласованные удалённые ссылки. Не использовать слепой `push --mirror`.
5. Обновить эту документацию, согласовать замену старых клонов и проверить ссылки pull request на GitHub. Для удаления сохраняемых GitHub копий при необходимости обратиться в поддержку; скрытые ссылки не считаются очищенными автоматически.

Сам аудит не удалил ни одного ресурса. Впоследствии выполнена [пробная очистка в отдельном локальном клоне](history-cleanup-trial.md): 18 объектов удалены, актуальное дерево не изменилось, сборка и smoke-тест прошли. Впоследствии очищенная `main` [опубликована на GitHub](history-cleanup-publication.md). Пункт очистки публичной истории остаётся открытым из-за старой ссылки `refs/pull/1/head`.
