# Публикация очищенной истории

## Выполнено

После [пробной очистки](history-cleanup-trial.md) незакоммиченные изменения подготовки релиза перенесены в очищенную историю отдельным коммитом:
`013bd166000b078fefd5c0dce182d77eb89c55e7` — «Подготовлены исходники runtime и проверена очистка истории».

Ветка `main` на GitHub заменена командой с явной защитой ожидаемого прежнего состояния:

```text
git push --force-with-lease=refs/heads/main:deb9e43110e46c26338f5b3536d7eb82470b9409 github HEAD:refs/heads/main
```

Изменялась только `refs/heads/main`, не зеркало всех ссылок. Сервер подтвердил замену; `git ls-remote --heads --tags` показал `main` на новом коммите без других веток или тегов. Последующие обычные коммиты документации продолжают эту очищенную историю.

На конечном состоянии кода и скриптов перед отправкой выполнен `mingw32-make dist-check`:

- сборка с `-Wall -Wextra -Wpedantic` без предупреждений;
- smoke-тест пройден;
- ZIP игры создан;
- проверка 63 контрольных сумм файлов, smoke-тест распакованной копии и изолированный запуск игры пройдены.

Журнал сохранён вне проекта в `sfmlgame-private-history-20261021-171552/final-dist-check.log`. Публичный релиз игры и исходников runtime ещё не опубликован.

## Оставшаяся ссылка GitHub PR #1

После force-push проверено `git ls-remote origin 'refs/pull/*'`. GitHub по-прежнему предоставляет:

```text
cf93f5c64b4f6e2db460ebe90beeab1cd01c901e refs/pull/1/head
```

API https://api.github.com/repos/Sergviva1/sfmlgame/pulls/1 подтверждает закрытый PR #1 со старым head и прежним merge-коммитом. Эта ссылка сохраняет доступность старой истории и ресурсов, несмотря на очищенную `main`.

GitHub управляет `refs/pull/*`; обычная отправка веток не позволяет удалить эту ссылку. Удаление старой ветки или закрытие PR само по себе проблему не решает: ветки на сервере уже нет, PR закрыт. Следует выяснить через поддержку GitHub доступные меры удаления старой PR-ссылки и сохраняемых копий. При необходимости отдельно выбрать дальнейший способ публикации репозитория. Результат обращения заранее не гарантируется.

Пока этот вопрос не решён, нельзя утверждать, что старые ресурсы полностью удалены с GitHub. Пункт истории ресурсов в SPEC остаётся открытым.

## Локальные копии

Приватная резервная копия исходной истории намеренно сохранена вне проекта. Она не предназначена для распространения. Локальные reflog и недостижимые объекты старой рабочей копии могут также хранить прежние коммиты; агрессивная очистка этих данных не выполняется для сохранения возможности восстановления.

Другим участникам следует заново клонировать репозиторий, а не сливать старую историю обратно. Не отправлять резервный bundle или прежние ветки на GitHub.
